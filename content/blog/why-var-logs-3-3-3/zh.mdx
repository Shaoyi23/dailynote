这是 JavaScript 里一道很经典的题：一个使用 var 的 for 循环、三个定时器，以及一个问题——最后会打印什么？常见选项包括 [0, 1, 2]、0, 1, 2、3, 3, 3 和死循环。

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}
```

如果你的第一反应是 0, 1, 2，你关注的是创建回调时 i 的值。这个猜测很合理，但 JavaScript 并没有为定时器保存那一刻的数字快照。

## 答案

<Callout label="正确答案">

C — 3, 3, 3

</Callout>

循环会在任何一个定时器触发之前同步执行完毕。等到回调真正运行时，唯一的 var i 已经变成了 3。每个回调各打印一行 3，所以最终输出是三个 3。

## 一个变量绑定，三个闭包

var 是函数作用域，在顶层则是全局作用域。因此三个回调闭包引用的是同一个 i。闭包没有捕获 0、1、2 这些值，它捕获的是变量本身。等回调真正读取 i 时，循环已经结束，值是 3。

> 定时器没有捕获值，它捕获的是变量。

## 剩下的交给事件循环

setTimeout 只是把回调交给定时器，然后立刻返回。循环顺利跑完，i 增加到 3 后条件不成立。直到这时，事件循环才处理到期的定时器。三个回调看到的 i 都是 3。

1000ms 也不是每次打印之间间隔 1 秒。三个回调差不多在同一时间入队，然后依次执行，所以三个 3 几乎同时出现。

## 换成 let 之后

把 var 改成 let，输出就会变成 0, 1, 2。在 for 循环中，let 会为每一次迭代创建新的绑定，每个回调捕获自己那一轮的 i，因此值被保留下来。

```js
for (let i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log(i);
  }, 1000);
}
```

## 其他捕获当前值的方式

如果必须使用 var，可以把当前值显式传给回调。setTimeout 支持传入额外参数，这些参数会原样传给回调函数。

```js
for (var i = 0; i < 3; i++) {
  setTimeout((value) => {
    console.log(value);
  }, 1000, i);
}
```

用立即执行函数（IIFE）也可以为每一轮循环创建新作用域，但通常写法不如 let 直观。

## 记住这几件事

- var 是函数作用域，let 和 const 是块级作用域。
- 闭包捕获的是变量绑定，而不是值的快照。
- 定时器回调要等当前同步代码执行完毕后才会运行。
- for 循环里的 let 会为每一轮迭代创建独立绑定。

这道题真正考的不是 setTimeout，而是代码写下的时间和它真正执行的时间之间的差距。理解这个差距之后，很多异步 JavaScript 问题都会变得清晰。
